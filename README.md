# ことばの記録 — 準1級EX・長文 苦手単語PWA

ホームから独立した「英作文マスター」も開けます。独自問題・答案履歴・手動評価・構文別演習・復習・教材進捗・自由英作文を専用領域に保存します。AI自動添削は未接続です。使い方・検証結果・制限は [英作文マスターの説明](./docs/WRITING_MASTER.md) を参照してください。

[APP_DESIGN.md](./APP_DESIGN.md)に基づく、Android / Chrome向け単語帳です。既存の **308語・固定ID・日本語訳を変更せず** `initial_words.json` から登録します。外部CDNやGoogle認証情報をアプリに置く必要はありません。

- IDごとの累積誤答・正答回数、最終学習日時・結果を端末保存。正解でも誤答回数はリセットしません。
- 全単語 / 誤答経験あり / 累積誤答が多い順で復習。開始・終了No.を指定した範囲内で、No.順またはランダム（重複なし）の出題を選択。検索付き履歴一覧。
- 登録元を「すべて／準1級EX／長文」で切り替え。同じ単語に両方の登録元を付けても1件の単語と共通の学習履歴を保持。初期308語はEXとして扱う。
- Sheetsの公開CSV、またはApps ScriptのJSONを起動時・前面復帰時・オンライン復帰時・手動で同期。訳・綴りが変わってもIDに紐づく履歴を保持。
- フィード取得失敗時も語彙・履歴を保持。行がフィードから消えても物理削除せず、`active=false` は利用者の確認後に非表示。
- 旧HTMLからの移行、新旧JSONのバックアップ・復元、オフライン起動・学習、ホーム画面からの単独起動。

## ローカル実行・テスト

Node.js 24以上を推奨。公開後の利用にはNode.jsは不要です。

```sh
npm ci
npm start
```

`http://localhost:4173/english-flashcards/` を開きます。Service WorkerはHTTPSまたはlocalhostで動きます。`file://` でHTMLを開く方法はPWA検証に使えません。

```sh
# Chromiumが未インストールの場合のみ
npx playwright install --with-deps chromium
npm test
# 復習画面・移行・バックアップ・オフライン再起動だけを確認
npx playwright test tests/browser/review.spec.js
npm run build
```

`npm test` はデータ処理の単体テストとPixel 7相当のChromiumテストを実行します。ブラウザテストは本番ビルドを `/english-flashcards/` で配信し、実際のService Workerを有効にします。`/usr/bin/chromium` があれば使用し、なければPlaywrightのChromiumを使用します。`CHROMIUM_PATH` で別パスを指定できます。

対象：308語、×5回→○1回、再読み込み、訳修正・重複同期、JSON移行・復元・破損拒否、取得失敗、前面/接続復帰、非表示承認、通信断後の再起動・学習、複数タブ、保存失敗、manifest・PNG・通常プロファイルでのインストール適格性。Android実機でのインストール操作と本物のSheets接続は、下記の設定後に別途確認してください。

## GitHub Pagesへの公開

1. この変更をGitHubの `main` または `master` にコミット・push、またはPRをマージします。
2. **Settings → Pages → Build and deployment → Source** を **GitHub Actions** に設定します。Actionsが無効なら有効化してください。
3. **Actions → Test and deploy PWA to GitHub Pages** の成功を確認します。pushで自動実行されます。Pages設定前に失敗した場合は **Run workflow** で再実行します。
4. deployジョブの公開URLを開きます。このリポジトリの標準URLは以下です。実際の公開完了はActions画面で確認してください。

```text
https://kiyotakalam-collab.github.io/english-flashcards/
```

[.github/workflows/pages.yml](./.github/workflows/pages.yml) はテスト成功後に `dist/` のみ公開します。PRではテスト・ビルドだけを実行します。相対URLなのでプロジェクト配下・独自ドメインのルート配信に対応します。

アプリ更新時はビルド時のハッシュでオフラインキャッシュを更新します。「同期・設定」の「新しいバージョンに更新」で適用できます。履歴・他アプリのキャッシュは削除しません。**Sheetsの単語追加だけなら再ビルド・再公開は不要です。**

## 既存の学習履歴を移す

**旧HTMLを使っているブラウザで、先にJSONバックアップを保存してください。**

1. 旧 `flashcard_mistake_tracker_1-1200.html` の「バックアップ (JSON)」で `flashcard_backup.json` を保存します。元HTMLはそのまま残しています。
2. 新PWAの **同期・設定 → JSONを取り込む** で選択します。
3. 内容を確認して承認し、「単語と記録」で正答・累積誤答回数を確認します。
4. 新PWAから「JSONを書き出す」で改めて保存します。

同一origin（プロトコル・ホスト・ポートが同じ）の旧localStorageキー `study_flashcards_mistakes_v1` は初回に一度だけ自動移行します。旧形式の取り込み時だけ、単語の空白・大文字小文字を正規化して既存IDに対応させます。旧キーは変更しません。308語以外の旧単語も履歴とともに取り込みます。

**ローカルHTML、別ドメイン・ブラウザ・端末の履歴は直接読めないため、JSON取り込みが必要です。**

取り込みは置き換えではなく統合です。各IDの正答・誤答はそれぞれ現在とバックアップの大きい方を残すので、回数が減らず、繰り返し取り込んでも増えません。独立した複数端末の回数を加算する機能ではありません。現在の訳・非表示状態・同期先を上書きしないため、新端末では同期URLを再設定してください。

履歴は端末内の `ex_flashcards_pwa_v2`（localStorage）に保存します。ブラウザデータ削除等で消える場合があるため、JSONを端末外にも保管してください。「長期保存をリクエスト」はブラウザの判断で許可され、バックアップの代わりにはなりません。

## Google Sheetsの接続設定

### 単語マスターの用意

1. Sheetsに **単語マスター** タブを用意します。
2. [initial_words.csv](./initial_words.csv)を **ファイル → インポート → アップロード** で対象タブに読み込みます。初期308語を元のIDで取り込めます。CSVは `node scripts/export-sheet.mjs` で原本JSONから再生成できます。
3. 次の7列を使用します（既存の6列フィードも読み込み可能）。ID列はプレーンテキストにしてください。

| 列 | 例 | ルール |
| --- | --- | --- |
| id | `clumsy` / `word-000309` | 必須、一意、決めたら変更禁止。既存308語はJSONのIDを使用 |
| word | `clumsy` | 必須、前後空白・大文字小文字違いも含め重複させない |
| meaning | `不器用な、ぎこちない` | 必須、確認済みの訳だけ |
| range | `1000-1200` | 任意 |
| active | `TRUE` | `FALSE` はPWA側で承認後に非表示 |
| updated_at | `2026-11-09T12:00:00Z` | 任意、更新日時 |
| sources | `ex` / `reading` / `ex|reading` | 登録元。空欄は未分類。両方に載った単語は固定IDを維持してタグを追加 |

CSVでは `id,word,meaning` が必須、残り4列は省略時に既定値です。`sources` は登録元が確認できた場合のみ指定します。古い6列フィードに `sources` がなくても以前の登録元を消しません。JSONは配列または `{"words":[...]}` を受け取ります。同一ID・完全同一内容の行は1件にまとめ、矛盾する重複や不正な列・型は同期全体を拒否して以前のデータを保ちます。単語修正時もIDを変えず、削除は行削除ではなく `active=FALSE` にしてください。


### 登録元の扱い

- `ex`：準1級EX。GitHub同梱の初期308語は、既存の学習履歴を変えずにEX扱いとします。
- `reading`：長文・過去問から確認して登録した単語。
- `ex|reading`：両方の出典で確認できた同じ単語。重複行を作らず、1つの固定ID・学習記録にまとめます。
- 空欄：出典未確認。勝手に長文扱いしません。「すべて」では出題されます。

PWAの「学習する」「単語と記録」で出典フィルターを切り替えられます。登録元ごとの出題番号は各フィルター内の番号です。通常の出題モード（全単語／誤答経験あり／累積誤答の多い順）との併用も可能です。

### 方法A：公開CSV（最小構成）

1. Sheetsで **ファイル → 共有 → ウェブに公開** を選びます。
2. **単語マスターのタブだけ**を選び、形式を **カンマ区切りの値 (.csv)** として公開。「変更が加えられたときに自動的に再公開する」を有効にします。
3. 発行された `https://docs.google.com/spreadsheets/d/e/.../pub?gid=...&single=true&output=csv` をコピーします。通常の `/edit` URL・共有リンクは使用しません。
4. PWAの **同期・設定 → 公開CSV / JSONのURL** に貼り付けて「保存して同期」を押します。
5. 最終同期成功日時・追加数・「同期済み」を確認します。初期308語だけなら追加数は0です。

Google側の公開データ反映に時間がかかる場合があります。アプリは毎回ネットワーク取得しますが、Sheets側のキャッシュ反映を早めることはできません。

### 方法B：Apps Scriptの読み取り専用JSON

こちらも **単語フィードは認証なしで公開されます**。

1. **拡張機能 → Apps Script** を開き、[google-apps-script/Code.gs](./google-apps-script/Code.gs)を貼り付けます。
2. **プロジェクトの設定 → スクリプト プロパティ** に `SPREADSHEET_ID` を設定。値はSheets編集URLの `/d/` と `/edit` の間のIDです。
3. **デプロイ → 新しいデプロイ → ウェブアプリ**。実行ユーザーは **自分**、アクセスは **全員（ログイン不要）** に設定。初回のSheets読み取り権限を承認します。
4. 発行された `https://script.google.com/macros/s/.../exec` をPWAに設定します。テスト用 `/dev` は使いません。
5. ログアウトしたシークレットウィンドウでもJSONが読めることを確認し、PWAで同期します。

リダイレクト先の `script.googleusercontent.com` を含め、ブラウザからCORSで読める公開設定が必要です。ログインやAuthorizationヘッダーは使用しません。組織アカウントで公開不可なら管理者の許可、または別途認証付きAPIの設計が必要です。コード変更時は既存デプロイを新バージョンに更新します。

コードは `doGet` のみで、公開エンドポイントに書き込み権限・学習履歴は渡しません。HTTP 200でも `{"error":...}` やログインHTMLならPWAは同期失敗として以前のデータを維持します。

### ChatGPT側の権限

**PWAの読み取りURLと、ChatGPTのSheets編集権限は別の設定です。** このコードを公開するだけではChatGPTのGoogle権限は追加されません。

- 利用中のChatGPT環境で **Sheetsへの書き込みを実際にサポートするアプリ・コネクター、または承認済みの外部連携** を接続し、対象ファイルを編集できるアカウントを認可してください。Drive検索・読み取りだけでは行追加できません。書き込み可否はプラン・アプリで異なります。
- 対象ファイル・タブを指定し、実データを確認してから編集し、書き込み後に読み戻してください。
- 以下を運用指示として使えます。

```text
指定したスプレッドシートの「単語マスター」を読み、wordのtrim+casefoldで重複を確認してください。
列は id,word,meaning,range,active,updated_at,sources です。sources は ex（準1級EX）、reading（長文）、ex|reading（両方）、空欄（未分類）。新語は一意の固定idで追加し、activeはTRUE。
既存語の修正ではidを変えず、出典は既存タグとの和集合にしてください。出典を推測しないでください。既存行を勝手に削除しないでください。
写真はマーカー語のみ対象とし、読めない語や不明な意味は登録前に確認してください。
書き込み後に読み戻せた場合だけ「反映済み」と回答してください。
書き込み権限がなければ追加用の7列CSVを作成してください。
```

書き込み連携がない場合も、CSVをSheetsへ手動追加すればPWAの自動同期は動きます。公開するのは単語情報だけにし、個人情報・学習履歴・Googleトークン・編集鍵は含めないでください。

## Androidでの確認

1. 公開したHTTPS URLをChromeで開き、308語と旧履歴の移行結果を確認。
2. 「同期・設定」で **オフラインの準備ができました** を確認。
3. Chromeメニューの **ホーム画面に追加 → インストール**、またはアプリ内インストールボタンを選び、ホーム画面のアイコンから起動。
4. 同じ単語を「最初から」を使って×5回→○1回で記録し、誤答5・正答1を確認。
5. 機内モードでアプリを閉じ、ホーム画面から再起動して学習・保存を確認。初回読み込みには通信が必要です。
6. 通信を戻し、Sheetsに新語を追加。前面復帰または「今すぐ同期」で1語増え、再同期では重複しないことを確認。
7. 既存語の訳だけを変更して同期し、累積誤答が変わらないことを確認。

同期はアプリを開いている時に行います。閉じている間の常時同期・履歴のクラウド共有・ChatGPTの常駐実行は行いません。新語は同期後に「最初から」を押すと出題セットに入ります。

## 範囲指定＋ランダム出題

「学習する」で登録元（すべて／準1級EX／長文）を選び、開始No.と終了No.を指定して「出題順」を「ランダム（重複なし）」にすると、**その範囲内の対象語のみ**をランダムな順番で出題します。登録元ごとにNo.は1から振られます。

- 一度のセッションでは同じ単語を重複して出題せず、No.そのものも変わりません。
- 「誤答経験のある単語」＋ランダムも併用できます。
- 「累積誤答が多い順」では苦手語の優先順位を維持するため出題順の切り替えを無効にします。
- 「この範囲で開始」や「もう一度学習する」で対象語を再シャッフルします。
- 出題順は表示時のみで、固定単語ID・累積誤答／正答回数・バックアップ・Google Sheetsの登録順は変更しません。

## 復習カレンダー・定着度

「復習・定着度」で、月ごとの復習予定と登録元ごとの定着度を確認できます。日付の区切りは端末のタイムゾーンにかかわらず **日本時間（JST）** です。前月・翌月・今月へ移動し、日付を選ぶとその日の対象語を確認して学習を始められます。「今日の復習を始める」と期限到来の一覧には、今の時刻までに期限が来た単語と、前日以前から期限を過ぎた単語を含みます。同じ日の予定でも、まだ期限時刻が来ていない単語はここに含めず、カレンダーの日付から確認できます。対象語がない場合は開始ボタンが無効になります。

正答時の復習間隔は、連続正答に応じて **1日 → 3日 → 7日 → 14日 → 30日 → 60日** です。誤答すると連続正答は0に戻り、**10分後**に短い再復習を予定します。累積誤答・累積正答はこれまでどおり加算し、正答しても過去の誤答を減らしません。復習期限より前に繰り返し正答しても、累積正答と解答履歴だけを追加し、連続正答と復習間隔は進めません。正答後の期限は回答時刻からの経過時間で決め、カレンダーではその時刻が属するJSTの日付に表示します。

定着度ダッシュボードは **未学習・要復習・定着途中・安定・再判定待ち** の5区分で、語数と各登録元の総語数に対する割合を表示します。割合は小数1桁に丸めるため、合計が100%と完全には一致しないことがあります。回答経験がなければ未学習、学習済みでも復習情報がない旧記録は再判定待ちです。新しい記録の最後が誤答、または現在時刻が復習期限を過ぎていれば要復習です。それ以外は、期限を迎えた復習で連続正答5回・30日間隔に達していれば安定、それ未満は定着途中です。同日中の反復正答だけで安定にはなりません。非表示の単語は集計・出題から除外します。

EXと長文の両方に登録された単語も、固定ID・学習履歴・次の復習日は1つです。各登録元の集計にはそれぞれ含まれますが、「すべて」では重複して数えません。復習画面の登録元を切り替えると、その登録元の予定から出題できます。

旧HTMLや復習機能追加前のバックアップには、正確な連続正答・次回予定がありません。累積回数・最後の結果・訳を保持したまま、連続正答0・予定なしとして読み込み、次の回答から予定を付けます。予定のない学習済み単語は「再判定待ち」として別集計し、期限到来の一覧やカレンダーには架空の予定を付けません。「学習する」で回答すると予定が付きます。過去の累積回数を連続正答へ換算しません。新しいJSONバックアップには復習予定と、今後の回答ごとの日時・正誤を持つ解答履歴も保存します。旧回数から過去の解答イベントを作りません。同じバックアップの繰り返し取り込みで累積回数や連続正答を加算せず、同じ解答イベントも重複しません。旧形式のバックアップも引き続き取り込めますが、復習情報を含むバックアップを旧バージョンのアプリで取り込むと、新しい復習情報は保持できません。

初回オンライン読み込みとオフライン準備の完了後は、カレンダー・定着度・復習予定の更新もオフラインで使えます。ブラウザのデータを削除すると端末内の記録は失われるため、定期的にJSONを書き出してください。
